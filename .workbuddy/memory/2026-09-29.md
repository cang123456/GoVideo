## 排查：nginx 反代后上传视频失败

**链路**：浏览器 XHR(FormData，字段名 `file`) → nginx 反代 → Go/gin `POST /api/upload` → `Uploader.Save`。

**结论**：不是 Go 代码问题，是 nginx 默认值卡在三个不同环节。

1. `client_max_body_size` 默认 **1m** → 视频必超，nginx 直接回 413，请求到不了 Go（前端 `JSON.parse` 失败，显示「响应错误」）。
2. `proxy_request_buffering` 默认 **on** → nginx 先把整个视频落到自己的 `client_body_temp_path` 再转发，多一次全量落盘，空间/断连即失败。
3. `proxy_read_timeout` 默认 **60s** → `handler.APIUpload` 在返回前**同步**执行 `Thumb.Probe`(超时 30s) + `Thumb.GenerateThumbnail`(超时 60s)，最长约 90s 不向 nginx 写任何字节 → 504。

**其他已确认的代码侧要点**：
- `main.go` 未设置 `r.MaxMultipartMemory`，用 gin 默认 32MB；超 32MB 的上传会先写系统 TEMP 再 `io.Copy` 到 `VideoRoot/uploads`，等于写两遍磁盘。（Go 的 `finishRequest` 会清 TEMP，不会残留。）
- `GenerateThumbnail` 第二次尝试（-ss 0）复用了同一个 60s context，若第一次已耗时较久，第二次剩余时间不足。
- 上传落盘目录固定为 `<VideoRoot>/uploads`，入库 `folder_path="/uploads"`。

**修复方向**：nginx 侧放开 body 限制 + `proxy_request_buffering off` + 拉长 `proxy_read_timeout`；代码侧建议把 ffprobe/截封面改成 goroutine 异步执行，落盘入库后立即返回。

**已确认**：用户截图显示 `POST /api/upload` 返回 **413 Content Too Large**（文件 530.4 MB，域名 videoxn--dw2ao72a.top），证实是第①关 `client_max_body_size` 默认 1m。已把 `static/js/app.js` 的前端兜底报错改为带状态码：`✗ 响应错误 (HTTP xxx)`。下一步需用户在服务器 nginx 配置加 `client_max_body_size 0;` 并 reload，同时建议一并放宽 `proxy_read_timeout` / 关闭 `proxy_request_buffering`，否则修完 ① 还会撞 ③(504)。

## 补充：Windows 环境变量设置

用户在本机 Windows CMD 里试了 `export VIDEO_NAS_ADMIN_KEY=...`（Linux 写法）失败。

**结论/要点**：
- Windows CMD 用 `set VIDEO_NAS_ADMIN_KEY=值`（当前窗口有效）、`setx` 永久（只对之后新开窗口生效）；PowerShell 用 `$env:VIDEO_NAS_ADMIN_KEY = "值"`。
- **CMD 里不能加引号**：`set X="abc"` 的值会包含引号 → 校验永远失败，且只报「密钥不正确」，极难排查。这是平台差异陷阱，值得长期记住。

**本次改动**：
- 新建根目录 `.gitignore`（此前缺失）：忽略 `data/`、`*.exe`、`*.db`、`admin-key.txt`、`.env`、`*.local.bat`、日志、`.idea/` 等。
- `README.md` 补充 Windows CMD / PowerShell 启动示例、`setx` 永久设置、以及生成强随机密钥的 PowerShell 单行命令，并加了 CMD 引号陷阱的警告。
